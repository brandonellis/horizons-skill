# Validate the experience with people

This is a study protocol, not completed user research. Recruit technical founders
and product/engineering leads unfamiliar with Horizons; use synthetic projects or
a participant's explicitly authorized source scope. Do not collect private data
or contact participants automatically. No in-product telemetry is installed.

Ask participants to: create a first roadmap from a repo and issue export; identify
what shipped since last week and open the proof; move an item and explain whether
it is saved; find the ticket/proof that could raise a grade; identify a shared
grade gate; and perform one task on a phone or using only the keyboard.

Record task completion, time to the first useful artifact, clarification rounds,
wrong-source or unsupported claims, scope/history regressions and whether the
participant can explain draft versus saved. Ask what decision the artifact helps
them make and what they would still need outside it. Do not coach toward success.
Record abandonment and missing access separately from model or interface failure.

Before making speed or adoption claims, compare the same task with the person's
normal workflow. Report participant count, tasks, model/host, tools, time windows,
failures and uncertainty. Small studies support iteration, not universal claims.
Use evals/RESULTS.md for agent runs and separate participant consented records for
human studies. No real-user outcome has been measured in this implementation.
